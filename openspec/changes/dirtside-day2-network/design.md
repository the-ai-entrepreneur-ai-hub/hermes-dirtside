# Design

## Context

See proposal.md for motivation. The day-1 executor, protocol, environment and relay are the starting point. All existing implementation and tests were read before this change. Core is read-only at `84a0301415edd6d1385207ec96e4d7f2b6c1fcd9`, Python 3.14.6. The other builder owns commands, prompt, desktop, benchmarks, README and target persistence. Those files and the targets schema will not be edited here.

## Goals / Non-Goals

Goals: outbound HTTP execution, pairing under either gate mode, exact identity and signature boundaries, lossless retries, bounded parallelism and clean process cancellation. Preserve the executor's `(Outcome, Chunk | None)` return and cancel Event.

Non-goals: service installation, another transport, sandbox claims, core edits, archive, main-spec sync or commits.

## Decisions

- **Shared runtime across loaders.** The auth provider holds the existing registry and relay as references. The independently loaded dashboard file obtains that instance through the public auth registry, then builds its router. This adds `hermes_cli.dashboard_auth.get_provider` to the routes' core imports, a narrow A3 deviation required by the verified loader. No core objects are patched and no second relay is created. The config boundary adds the verified home helper, another necessary A3 addition.
- **Agent ownership.** One long-lived HTTP client, one poll thread and an executor pool sized by `max_parallel`. Running entries are cancellation Events, not Popen objects, because the unchanged executor owns the groups and its cancellation channel is the Event (A16). The pool itself bounds active executor threads; a redundant semaphore is unnecessary. Polling continues at capacity so cancels and revocation cannot be starved by a long command. Retry waits observe shutdown and per-request cancellation. A rejected chunk returns False to the executor, which kills its group. A result follows executor completion; rejection cancels its remaining upload rather than killing naturally surviving background jobs.
- **Signals and retries.** The main-thread entry installs and restores SIGINT/SIGTERM handlers. Shutdown sets every Event and waits for executor cleanup before closing the client. Thread-hosted tests pass a stop Event. Poll errors back off 1, 2, 4 seconds to 30; uploads re-sign the same body and keep its sequence across retries, stopping on 2xx or 410. Chunk retries obey the execution deadline so a blocked send callback cannot extend the command timeout; that rejection is reported as exit 124. Terminal results can retry after the process has stopped. A 401 on any device post stops the whole agent. Every poll verifies the pinned relay key, sender, kind and replay guard before dispatch.
- **Private config and status.** Atomic 0600 JSON stores the seed and pinned public key, compiled positive policy caps and deny patterns. Remote URLs require HTTPS; plain HTTP is allowed only for loopback tests. A bounded private local log records contact and request ids/outcomes, never bearer tokens, scripts or command output. Status reads that log without sending a poll that could claim work.
- **Route boundary.** Bearer lookup precedes JSON decoding. Pending bearers work only for hello and verify with its untrusted key before hello parsing. Paired bearers verify the stored key and sender, touch only after verification, then parse and call the domain. Poll request bodies must be empty. Device request ownership is checked inside relay methods before feed or finish. A result feeds its optional typed tail and invokes the existing single close transition.
- **Pairing race.** Completion keeps its one transaction and additionally binds the authenticated code inside that transaction. A code replaced between lookup and completion cannot consume the newer same-name pending row. This changes no schema or target methods.
- **Desktop contract.** Devices returns active public facts, online and wall-clock last_seen. Target JSON is `{"target": "server" | "<device name>"}`; no stored target uses the configured default. A stored revoked device returns 404 rather than an internal id or a silent server fallback. Requests returns recent rows with a UTF-8 replacement-decoded live tail, pairing accepts `{"name": ...}`, revoke cancels all live requests. Explicit server persistence remains the other builder's target-method contract.

## Risks / Trade-offs

- A pinned key is trusted at pairing through HTTPS or an explicitly local HTTP URL. Signature checks cannot authenticate an already compromised pairing endpoint.
- Launch-process auth registration is the core contract. This change does not claim independent secondary-profile device fleets.
- Requests accepted while all workers are busy wait in the executor pool; execution stays bounded and cancellation remains live.
- The unchanged executor cannot observe an Event during a blocked HTTP call. Upload timeouts are short and retry waits interruptible, bounding shutdown delay.
- Gateway restarts lose live handles but keep the registry and relay seed. A subsequent upload returns 410 and stops the request; another poll succeeds without pairing again.
- An agent killed with SIGKILL cannot clean its detached shell groups. The gateway detects loss in 50 seconds and retains flushed output; the test explicitly cleans its orphaned test group.
- Natural background jobs survive normal completion, as required by R10. The local log is operational history, not a command-content audit.

## Migration Plan

Install the same plugin on gateway and device, enable it in the gateway launch home, mint a code under a dashboard session, pair over HTTPS and run serve. Existing registry files and tokens remain valid. Roll back by stopping the device and disabling the plugin; no main specifications or target schema are migrated here.
