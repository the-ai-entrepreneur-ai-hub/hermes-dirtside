# Sender-owned devices

## Why

Bind pairing and every dispatch to the admitted sender rather than sharing devices with the whole gateway.

Review point, verbatim (2026-11-08):

- [commands.py](https://github.com/the-ai-entrepreneur-ai-hub/hermes-dirtside/blob/0ae9359b4bd29114072343983abd0b624269acc3/dirtside/commands.py#L49-L79): paired devices are shared across the whole gateway, so any admitted user can `/dirtside use`, `pair` or `revoke` the owner's device. Bind each device to the sender who paired it, or add an owner allowlist (defaulting to that sender) and check it in all three commands.

## What changes

- Add tests/test_review_device_owners.py for commands, visibility, minting, identity spoofing, config and migration generated by the old registry code.
- Add Access, registry migration and owner model field; wire ctx and owners into commands, provider, prompt and auth/local IPC.
- Extend the real-core rig sender binding and add tests/test_review_device_owners_core.py for group terminal/file turns and defaults in both transports.

## Capabilities

### New capabilities
- `dirtside-review-device-owners`: The requirements and executable scenarios in this change.

### Modified capabilities
None.

## Impact

Plugin modules, tests and documentation change without changing signed device protocol version 1 or dependencies.

## Default trust and name ownership

Prevent configured-default and revoked-name squatting, name unprivileged ownership in privileged explicit confirmations, and state the limited pairing-name availability disclosure.

## Displaced work cancellation

Cancel the displaced owner's live relay requests immediately after a privileged cross-owner pairing succeeds. Desktop implicit target display must apply the same owner trust rule as dispatch.

## Native local authority

Recognize core's canonical local platform and surface only for an empty user or this process's exact uid subject. Prove the real authenticated CLI and TUI slash/turn demo in temporary homes, preserving wrong-uid and messaging refusals.

## Relay ingress provenance

The policy-free local-surface branch requires actual core command-source provenance that relay wire cannot forge. Native CLI/TUI slash and turn paths retain local authority. Dashboard logins map to the host owner, while Windows host subjects remain unsupported.
