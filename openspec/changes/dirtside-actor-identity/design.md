# Design

## Context

See proposal.md for motivation. All sender decisions converge on `Access.identity()`. Hermes 0.23.1 binds actor values through `SessionContext` and rereads a live turn event, including from copied contexts. Older cores' public reader falls through to the environment for an unknown actor name, even inside a bound turn. An unbound actor on a capable core can also read as `None`. Core invokes `pre_llm_call` once at the start of a turn, before its model loop; it does not update target facts after input joins that running turn.

## Goals / Non-Goals

**Goals:** Keep sender authority in one lookup, refuse an empty identity with a named route on every platform without a host fallback, preserve listed empty-route fallback, disclose legitimate default-to-server execution at turn start, and exercise real context construction, the real turn loop, event merging, scoped follow-ups, command dispatch, terminal/file middleware, hook facts, frozen sections, worker IPC and launch-environment isolation.

**Non-Goals:** Change routing keys, frozen-prompt caching, pairing or revoke semantics, protocol, dependencies, minimum core version, private import inventory, host provenance or implicit server defaults.

## Decisions

- Probe `find_spec("gateway.approval_actor")` once at import, returning false on discovery errors. Core publishes two names from that module, `approval_refusal` and `refusal_text`, not the whole module. It is absent at `8d7061f` and `84a0301`, and present at `3b42157`; these checkouts do not establish when it arrived. Module presence is the plugin's sign of actor binding. A direct import would be reported as private by the older cores' validators. An ungated test uses the real builder and binder with different actor and route users, comparing the probe with the public reader rather than trusting the probe to skip. A child also removes the unpublished setter and forces discovery errors. A wrong "no actor" answer keeps the first sender after a merge on an actor-capable core; a wrong "actor" answer on a core that binds none lets an environment actor stand in for the sender. The tests catch both directions on the cores CI runs. Only a capable core reads `HERMES_SESSION_ACTOR_ID`, with a `None` default; only `None` falls back to the route. This avoids older readers' environment fallback. A truthiness fallback would restore the first sender after a merge; inspecting an unpublished setter or private variable would cross the plugin boundary.
- Return missing identity before host and cron branches when the actor is empty and the route names a user. Empty actor plus empty route retains established no-user exceptions. A local wire label alone remains insufficient.
- Before default-owner fallback, guard either a chosen or captured default device using one sender snapshot and one route read. Empty identity with a nonempty `HERMES_SESSION_USER_ID` refuses on every platform, with no server execution. With both identity and route empty, refuse except on the plugin's eleven listed surfaces: empty platform, `api_server`, `cli`, `desktop`, `gateway`, `kanban`, `local`, `msgraph_webhook`, `tool`, `tui` and `webhook`. Only those user-less turns keep default-to-server fallback. Retain device-side revalidation, so a loss between checks cannot turn a device call into a host call. Strip and lowercase the bound platform; source alone cannot change the decision. Tests cover normalized listed and messaging values, parameterize core's real set and require a plugin subset with exactly one unlisted core surface, so additions fail for review. Known non-owners keep server fallback. The hook reads the captured default and emits the server line at turn start, not after a merge. Refused devices disclose no new facts. Explicit server and cron retain their rules; untouched server-default conversations stay silent.
- Bare status recognizes only the guard's `NoSingleSenderError` subtype and reports that no device applies, preserving its refusal and recovery text. It neither rereads identity nor matches message text to classify the error. An unpaired default keeps its existing status even beside an invalid sender. Real messaging command tests keep the owner's online-device controls; a listed-webhook test checks both the typed refusal's single sender read and the retired-device case.
- Replace the relay-local fixture's fabricated context with the actual `SessionContext` using common fields. No guessed version-specific fields are added. Its no-facts assertions stay; the single old silence assertion now expects the fixed server line only for an unauthorized implicit default.
- The integration fixture builds actual shared `SessionSource`, `MessageEvent` and `SessionContext` objects, calls the core binder and `absorb_turn_input`, and retains a copied tool context across the merge. Named-route merged negatives refuse chosen and default devices without host writes or more device requests. Real-binder tests also cover canonical CLI `local`, `webhook`, `api_server` and wire-relay-labelled `local` with named routes, owner and same-sender controls for both choices; they do not claim normal core merges on those surfaces or exercise relay admission. Constructed empty-route shared bindings on `webhook`, `api_server`, `msgraph_webhook` and `local` retain default-to-server fallback after the actor clears; a chosen device refuses, and Telegram refuses both. The bundled Telegram paths set the shared-session flag on non-DM input. A bundled group-DM path also sets it, but its `dm` classification retains the route user. The relay decoder carries neither that flag nor an event user. A valid named webhook sender keeps its device on every core; a missing identity or unprintable webhook user beside a named route refuses both chosen and default devices even on older cores. A small rig helper runs real `AIAgent.run_conversation` against core's scripted loopback server: the first tool call reaches the device, redirect absorbs another sender, and the second refuses while the original device facts remain and the hook count stays one. No hand-invoked mid-turn hook stands in for core behavior. A real `TurnState` and `scoped_turn_actor` test checks follower authority, opener steering and restoration. Inputs come from the owned stdio rig, not a live chat service. Capability checks skip actor-event cases on older cores; the independent probe/binder, incoming sender-less and bound-route/environment regressions run on all three.
- Remove all inherited `HERMES_SESSION_*` names and `HERMES_CRON_SESSION` before test collection. Tests deliberately planting values still do so after startup. A child launched with planted session and cron values imports test setup and reports the remaining environment, public values and missing sender, proving isolation even from a clean parent shell.
- Add a separate release CI job pinned to `3b421578588243f920886e6fe79a6faa87ea026e` on Ubuntu and macOS. Preserve the existing pinned job byte-for-byte. Run the existing report-only loopback benchmark on the release too.

## Risks / Trade-offs

- Older cores run another sender's queued follow-up inside the opener's binding, merge pending/batched input under the first source, and share threads by default. Mitigation: do not use device targets in any multi-sender shared conversation on those cores; use separate conversations or 0.23.1 or newer.
- Frozen sections and shared conversation history retain earlier facts and participants' text. Mitigation: refuse an empty identity with a named route on every platform instead of silently switching to the host, test the real loop with unchanged facts, disclose legitimate server fallback only at turn start, and explain that device authority is not input or history privacy. A constructed empty-route merge on a listed surface still falls back from a default device; no bundled path was found to produce it off Telegram, which is unlisted and refuses. Do not rebuild cached prompts.
- Direct ACP can bind a key and cwd without a public surface. Mitigation: preserve refusal of an explicit device and existing default-to-server fallback when identity and route are both empty; actor support invents no missing provenance.
- Three transitional private imports and process-owned dashboard auth remain. Mitigation: verify the exact import inventory and clean-export install decision on all three cores.

## Migration Plan

No data migration or device re-pairing is required. Run source-changing quick gates, including collection/counts, citations, clean-export admission/private checks and doctor on all three cores, before freezing the complete source and cumulative checkpoints. The final short verification runs the latest core's full suite and the changed test files once on each core; CI covers the pinned core and 0.23.1 on Ubuntu and macOS. If a later fix changes source, save its new manifest before any further run. Keep prior report content and supplied owner evidence intact. Reverting sender lookup restores shared/merged-turn and environment-override bugs; reverting the resolver guard restores silent mid-turn host execution on the routes it protects; reverting the server line hides legitimate default fallback. Prefer a focused forward correction if verification finds a problem.
